# mise compatibility harness

`run.sh` is a disposable Milestone 0 harness. It creates a temporary Git
repository for the backend fixture, then runs each check against the pinned
minimum mise release and the latest stable release. Every case receives fresh
`HOME`, `MISE_CONFIG_DIR`, `MISE_DATA_DIR`, `MISE_STATE_DIR`, and
`MISE_CACHE_DIR` directories.

The fixture only records the documented backend context and creates a tiny
`mise-skills` executable. It is not the product backend or CLI. This keeps the
compatibility checks independent of later milestones while proving the
runtime contract they rely on.

The pre-tools configuration generated by the harness has this shape:

```toml
[plugins]
"vfox-backend:skills" = "<plugin-url>#<plugin-commit>"

[bootstrap.hooks.pre-tools]
run = "ensure-minimum.sh mise 2026.6.14 && bootstrap-plugin.sh skills <plugin-url> <plugin-commit>"
```

`bootstrap-plugin.sh` reads the installed plugin's remote URL and checked-out
commit. It does nothing when both match, and uninstalls/reinstalls only when
the URL or commit differs. It never performs an unconditional forced install.
`ensure-minimum.sh` exits with status 78 and an actionable upgrade message
before a `skills:*` tool can be resolved by an older mise.

Run it from the repository root:

```sh
skills/mise/mise-skills-tests/run.sh
```

Use `MISE_SKILLS_LATEST_MISE_VERSION` or the binary override variables from
`run.sh --help` when reproducing a release-specific result. Set
`MISE_SKILLS_KEEP_TEMP=1` to inspect a failed fixture.
